#### 社内管理会計アプリ開発案件（2022/09 ～ 2024/12）

**概要**

社内向けの管理会計データを集計・計算し、各種レポートとして確認・提出できるWebアプリケーションの開発案件。

顧客の「こういうものを作りたい」という構想段階からPoCを作成し、その後の本開発・運用まで一貫して担当しました。エンジニア2名体制で、主にバックエンドの設計・実装を担当しました。

**利用した技術**

* Ruby on Rails
* Next.js
* graphQL
* PostgreSQL
* Terraform

**担当領域**

- バックエンドの設計・実装
- データ設計
- コードレビュー
- データ連携・運用改善

**詳細**

* 顧客の構想段階からPoCの開発に参加し、約2年間にわたって継続的に機能開発・改善を行いました。バックエンドを中心に担当し、フロントエンド担当のエンジニアと設計・レビューを相互に行いながら開発しました。
* 年度・半期・四半期、顧客・部門・案件など複数の切り口での集計や、前年比・予算比などの管理会計向けの計算処理を担当しました。
* 「バックエンドでデータを取り込み、必要な計算を行った上でフロントエンドへ提供する」という責務分担を意識して設計し、フロントエンド側では表示に集中できる構成としました。
* データの追加・変更・紐付け変更などを追跡できるよう、データ変更履歴やインポート履歴、差分を確認できる仕組みを設計・実装しました。データの不整合や集計結果に関する問い合わせに対して、データの変化を追跡しながら原因を確認できるようにしました。
* 当初はファイルによるデータ連携を行っていましたが、運用やデータ連携方式を見直し、既存のデータベースからのデータ連携にも対応しました。従来のファイル連携も維持し、状況に応じて複数のデータ連携方式を利用できるようにしました。
* 本番運用後も毎月のデータ取り込みや集計結果に関する問い合わせ・調査・不具合対応を担当し、実際の運用状況を踏まえた継続的な改善を行いました。
* 管理会計で利用する年度・半期・四半期などの期間計算について、アプリケーション内で複雑なロジックを持つことを避けるため、汎用的なRubyライブラリとして切り出してOSS化しました。アプリケーションから責務を分離することで、テストや保守をライブラリ側に集約し、アプリケーションの複雑性を低減しました。
* OSSライブラリでは年度の開始月を変更できる機能も実装し、特定のアプリケーションに依存しない汎用的な設計としました。
* 運用体制の変更に伴い、外部の運用担当者へシステムを引き継ぐ可能性が生じた際には、バックエンドのデータ構造や設計意図、運用上の考慮事項などを説明し、システムの理解・引き継ぎを支援しました。
